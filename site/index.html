System overview

What is Reframe?

Reframe is a writer-facing studio for turning a manuscript into a structured, inspectable working space. It helps a writer read, question, reshape, and compose from source material while keeping decisions, uncertainty, and system effects visible.

Purpose

A writing system with evidence

Reframe is not a generic chat assistant or an autonomous publishing system. It provides governed operations around a writer's work and explains what each operation can establish.

System boundary

Source, reasoning, action

The runtime reads source material, reasons over the current working state, and dispatches owned capabilities. Persistent project state and operational proof remain separate from conversational wording.

Reader contract

Inspect before you trust

The Book documents the development surface as a set of checked projections: command inventory, capability registry, live acceptance, and named-build release status.

Operating model

From source to checked result.

Reframe separates the writer's material, the reasoning that interprets the current state, the operation that acts, and the evidence that makes the result reviewable.

  1. 01 · SourceA manuscript and its confirmed working context.
  2. 02 · ReadingStructure, questions, and uncertainty are made inspectable.
  3. 03 · CapabilityA governed operation is selected with its policy and preconditions.
  4. 04 · ResultThe action produces a visible, persisted application result.
  5. 05 · EvidenceAX, visual, telemetry, and store proof establish what happened.

Routing policy

Paid is the default election.

When an eligible paid lane is available, Reframe resolves it once with its provider and budget. Bounded, private, deterministic, and offline work may remain on-device, and an explicit local-only instruction overrides the default. Internal delegation is not a second writer-facing persona.
